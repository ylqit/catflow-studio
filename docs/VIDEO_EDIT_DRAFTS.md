# 问题视频编辑草稿与帧时间轴

本轮边界：问题视频可以进入非破坏性草稿，不等于正式验收；局部模型结果只有通过明确操作才能进入新草稿版本。PostgreSQL 保持唯一业务状态源。

## 数据与工作流

`0027_video_edit_drafts` 新增 `video_edit_drafts` 与不可变 `video_reviews`，复用 `edit_versions` 的 EDL，而不是保存浏览器专属剪辑事实。

1. `POST /projects/{id}/video-edit-drafts` 从可读取、属于项目的视频创建草稿（携带幂等键）。不要求该视频已选中，不改写原选择。
2. 当前草稿版本的 EDL、源视频 SHA256、来源冻结参考组成修复输入。已有专业参考不隐式替换为当前 Canon；缺少历史参考时需要明确确认。
3. 免费完整预览通过 `render_edit_preview` 本地 Job 物化，成功结果是 `edit_preview` Asset，不是正式输出。
4. 局部修改创建一个显式付费 Job，冻结父版本、完整 EDL、时间线哈希、范围、指令和结束策略。不自动重试。
5. 结果为 `candidate_ready`。免费完整合成对比仍不改草稿或正式视频。
6. 用户“应用到草稿”时提交预期父版本与哈希。后端重新校验精确拼接结果，创建不可变新版本，将状态标为 `applied_to_draft`。旧版本保持可读。
7. 完整草稿验收绑定准确的 Asset、EditVersion 和时间线哈希；全部真实通过后才允许正式视频选择。普通资产选择接口不能绕过视频验收。

草稿不能直接走正式导出接口。正式选择完整视频之后才进入原有剪辑/正式输出流程。旧历史选择不追溯改写。

## 时间范围

全部使用 24 fps 整数帧、半开区间 `[startFrame, endFrame)`：

- 问题/替换范围：最少 1 帧。
- 生成上下文：为动作和接镜扩展至 Provider 能力允许的 4–15 秒；它不是用户问题范围的下限。
- 候选取用范围：从模型视频内取等长片段，不把 Provider 补足帧放回成片。

289 帧饼干案例：替换 `[144,289)`；上下文 `[120,289)`；Provider 8 秒；候选取 `[24,169)`；合成仍为 289 帧。

模型指令使用片段内部时间（该案例 1.000–7.042 秒）。全局时间用于 UI/审计，不能直接当作参考片段的时间。

## 时间线与媒体边界

`LocalMediaJobExecutor.render_timeline` 同时承担完整预览、参考片段/锚帧提取和后续合成的时间线解释。Worker 读取冻结 EDL，而不是重新读取当前选择或退回根视频。

- v2 校验项目归属、SHA256、来源范围、片段长度、总帧数、音轨和候选来源。
- v1 的裁切、转场与音轨先按旧 EDL 本地物化，之后才建立 v2 基底。不会忽略旧剪辑。
- 无损历史策略指业务内容不可变，不承诺 FFmpeg 重编码逐字节无损。
- 新拼接片段 ID 根据修复身份和来源范围确定性派生，因此 Preview、保存、幂等重放使用同一时间线哈希。
- 预览缩略图为本地静态帧序列，有明确源帧号；恢复落盘可以补齐缺失缩略图而不重复创建主预览。
- v1 `native_fades` 现在实际应用音频淡入淡出，不再仅转码为 AAC；这是保留原剪辑语义的缺陷修正。

## 结束状态

- `match_original`：原结尾正确，使用出点参考衔接。
- `replace`：原结尾也错误，用户必须给出期望状态，不把原错误出点锚帧提交为必须匹配的约束。
- 片尾没有下游出点接缝；UI 显示“不适用”，后端验证确实到片尾。
- 指令在 API 编译一次；Ark v3 路径不再次套入相互矛盾的旧模板。
- 期望状态通过与整片 Prompt 共用的句子边界编译器处理，只规范化连接边界，不改写数据库原文。

## 前端状态

`FrameTimeline.vue` 统一轨道内容矩形、手柄、色块、播放头与上下文的坐标系。范围约束只作用于值，不改变手柄坐标域。滚动和时间轴缩放自然进入内容矩形计算。

- 拖动使用 pointer capture，支持整体移动和方向键逐帧调整。
- 时间码/帧数调整会定位实际播放器；排除式出点显示最后包含帧。
- “预览定位帧”独立于替换区间，提交后仍能检查视频而不修改冻结范围。
- 播放头优先使用呈现帧回调；seek 等待解码完成；片尾循环结合 ended 处理。
- 草稿 URL 保存稳定 draftId；任务、候选和冻结范围从服务端恢复。
- 网络结果未知保留幂等键，不自动重提；已存在非终态 Job 时保持输入锁定。

## 验证与限制

- 后端测试覆盖：未选中问题视频建草稿、正式选择拦截、幂等/CAS、1 帧范围、完整 EDL 重复编辑、实际 FFmpeg 289 帧合成、旧 v1 裁切/静音、错误尾帧排除、SDK 指令不重复编译。
- 浏览器验证和真实模型效果分别记录在 `output/playwright/video-edit-cookie-20260905/`。通过测试不等于模型已经修好饼干；必须实际比较完整视频。
- 精确替换帧不代表模型能保证一帧级语义修复。片段内容、身份、接缝与音轨仍需人工验收。
- 迁移只新增结构和兼容约束；降级拒绝自动丢弃新草稿/验收历史。上线前备份，不把迁移当作可随意回滚操作。
