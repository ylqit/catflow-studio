# 放风筝三片段完整生产运行手册

> 最后核对：2026-08-19
> 适用版本：CAT-VIDEO-GENERATOR V5，数据库 Revision `0018_v5_shot_assistance`
> 目标产物：两个场景、三个独立 12 秒视频片段，合成为约 35–36 秒的 9:16 竖屏短片
> 适用平台：Windows PowerShell、FastAPI、Vue、PostgreSQL、火山方舟、FFmpeg

本手册用于从一个干净的“放风筝”项目开始，完成剧情、分镜、视觉资产、开场锚点、视频审核、尾帧衔接和本地成片。它是生产操作手册，不修改代码、数据库结构或既有项目数据。

生产主链路如下：

```text
完整剧情
  → 可选剧情诊断/重写
  → 分镜导演与人工定稿
  → 按需准备服装、环境和风筝资产
  → 场景视觉基准
  → 片段静态开场锚点
  → 三个片段分别生成和审核
  → 上一片段尾帧衔接
  → FFmpeg 本地合成
```

## 1. 当前系统实现与环境状态

### 1.1 已实现边界

- 后端为 FastAPI，前端为 Vue，业务数据持久化在 PostgreSQL。
- 全局 Canon、项目、场景和片段资产分别使用 `canon`、`project`、`scene`、`shot` 归属。
- `ShotGenerationSpec` 是制作看板、片段工作区、Prompt 预览和真实视频提交的统一生成规格来源。
- 视频输入模式互斥：
  - `text_only`：不提交图片；
  - `reference_media`：提交普通参考图片；
  - `first_frame`：只提交一张批准的开场锚点。
- 长任务提交后由全局任务中心追踪，持久化 `workflow_steps` 的状态优先于进程内状态。
- 三个 12 秒片段分别调用视频模型；每个片段内部的 2–4 个编号子镜头属于同一次生成。
- 片段批准后可提取尾帧，最终使用 FFmpeg 合成为一个视频。
- 数据库保持 `0018_v5_shot_assistance`，本流程不要求新增迁移。

## 3. 项目和剧情定稿

### 3.1 项目设置

在 Studio 中新建项目 `放风筝-正式制作-20260819`，初始化 Canon 档案。默认人物、猫咪和画风均继承全局 Canon，不为项目复制一套新的身份图。

### 3.2 场景一：窗边制作风筝

- 场景模式：单片段。
- 目标片段数：1。
- 目标片段时长：12 秒。
- 场景标题：`窗边制作风筝`。

完整剧情：

> 春日上午，柔和的自然光落在屋内靠窗的小木桌上。五至七岁的短波波头东亚小孩穿着浅米色短袖上衣、柔和蓝灰色短裤和浅色帆布鞋，坐在桌前完成一只菱形纸风筝。风筝采用浅米白纸面、柔和天蓝色包边，中心画着简洁的橙色太阳和两朵白云，细竹骨架已经固定完成，桌边放着蓝、粉、黄色组成的短尾带。
>
> 同一只灰白短毛猫蹲在旁边椅子上，没有帽子、项圈或背包。小孩拿起彩色尾带准备绑到风筝尾部，垂落的飘带轻轻晃到猫咪面前。猫咪先用眼睛追随飘带，随后自然探出一只前爪，前爪恰好轻轻压在风筝靠近桌边的一角，使风筝没有滑动。小孩顺势把尾带系好，抬头发现猫咪无意中帮了忙，露出温和笑容。最后小孩稍稍举起完成的风筝，猫咪凑近嗅闻垂下来的彩色尾带，画面停在风筝、小孩和猫咪都清晰可见的稳定状态。

### 3.3 场景二：草地放飞风筝

- 场景模式：多片段。
- 目标片段数：2。
- 每个片段时长：12 秒。
- 场景标题：`草地放飞风筝`。

完整剧情：

> 午后，小孩仍穿着室内制作风筝时的同一套春日常服，带着完成的菱形风筝和灰白猫来到开阔的春日草地。草地平缓开阔，远处有低矮树木和浅色步道，天空清澈，风力温和稳定。人物、猫咪和风筝外观必须与室内场景保持一致。
>
> 小孩先把风筝迎风立在草地上，一只手握住线轴，另一只手扶正风筝。猫咪站在风筝尾带旁边，先观察随风轻摆的彩色飘带。小孩慢慢后退，风筝纸面被风撑开，线逐渐绷紧，风筝从草地上平稳离开。猫咪跟着飘带向前跑几步，但不咬住或破坏风筝。
>
> 风筝升高后，小孩双手控制线轴，在草地上轻快向前移动。风筝的影子掠过草地，猫咪把注意力转向移动的影子，自然追跑并轻轻扑跳一次。小孩停稳脚步看向猫咪，露出开心笑容。最终风筝稳定飞在蓝天中，小孩和猫咪位于画面下方，画面停在温暖、清晰、可以作为故事结尾的远景状态。

### 3.4 剧情流程选择

本手册已经提供完整人工定稿，推荐：

1. 直接使用“完整剧情”入口，不调用一句话主题扩写。
2. 剧情诊断为可选步骤；需要 LLM 再检查道具、动作和因果时才运行。
3. 本稿不强制剧情重写。诊断后可选择“保留原稿直接进入分镜”。
4. 分镜导演是进入生产阶段的必经步骤。
5. 每次 LLM 调用前确认模型、输入和费用；任务完成后人工编辑并接受。

## 4. 三个片段的分镜定稿

接受分镜导演结果前，将三个片段调整为以下内容。每个片段只表达一个生活微事件，不写虚构的精确秒点。

### 4.1 片段一：猫咪意外帮忙系好风筝尾带

- 时长：12 秒。
- 开场方式：根据视觉资产生成独立开场图。
- Provider 视频模式：批准锚点后使用 `first_frame`。

分镜正文：

> 1. 中景固定机位，春日窗边木桌完整入画。小孩坐在桌前，尚未系好的彩色尾带垂在风筝旁边；灰白猫蹲在相邻椅子上，视线跟随轻轻晃动的尾带。
>
> 2. 近景轻微跟随，猫咪自然探出一只前爪，前爪轻轻压住风筝靠近桌边的一角。小孩双手把彩色尾带绕过风筝尾部并系紧，动作顺序清楚，风筝、竹骨和尾带不穿透、不变形。
>
> 3. 中景稳定收尾，小孩发现猫咪无意中帮忙，微笑着把完成的风筝稍稍举起。猫咪收回前爪并凑近嗅闻垂下的尾带。保留纸张轻响、飘带摩擦和室内自然环境声，无对白。

### 4.2 片段二：草地上准备并让风筝离地

- 时长：12 秒。
- 开场方式：根据场景资产生成独立开场图。
- Provider 视频模式：批准锚点后使用 `first_frame`。

分镜正文：

> 1. 中远景平拍，开阔草地和远处低矮树木入画。风筝迎风立在草地上，小孩一手扶正风筝、一手握住线轴；灰白猫站在彩色尾带旁边观察，风筝尚未离地。
>
> 2. 侧面中景缓慢跟拍，小孩松开扶风筝的手并向后退两三步，双手控制线轴。风吹开纸面，风筝沿迎风方向平稳离开草地；猫咪跟随摆动的尾带向前跑几步，但不抓住尾带。
>
> 3. 中景稳定收尾，风筝升到小孩头顶上方，线已经绷紧。小孩抬高手中的线轴，猫咪停在脚边抬头观察。保留风声、草叶摩擦和线轴轻响，无对白。

### 4.3 片段三：风筝升空，猫咪追逐影子

- 时长：12 秒。
- 开场方式：优先采用片段二批准视频的尾帧。
- Provider 视频模式：尾帧被批准为开场锚点后使用 `first_frame`。

分镜正文：

> 1. 延续上一片段尾帧中的人物、猫咪、风筝高度、线轴方向和草地位置。小孩控制线轴向前轻快移动两三步，风筝继续稳定升高。
>
> 2. 低机位跟随猫咪，风筝影子从草地上掠过。猫咪自然追跑并朝影子轻轻扑跳一次，随即四足落地；小孩在背景中稳住线轴，人物和猫咪动作方向保持连续。
>
> 3. 全景缓慢拉远，风筝稳定飞在蓝天中，小孩停下脚步看向猫咪并露出笑容，猫咪站在旁边抬头观察天空。画面稳定停在风筝、小孩和猫咪形成完整关系的远景。保留自然风声、草叶声、脚步声和线轴轻响，无对白。

### 4.4 分镜接受检查

- 场景一严格生成 1 个片段，场景二严格生成 2 个片段。
- 每个片段为 12 秒、3 个编号子镜头。
- 猫咪是主要观察和行动对象；人物承担制作、拿取和线轴操作。
- 三个片段没有重复完成同一动作，也没有遗漏风筝状态变化。
- 原始 Provider 输出和人工接受稿均保留在工作流历史中。

## 5. Canon 与视觉资产规划

### 5.1 全局 Canon

项目继承以下全局批准资产：

- 人物大头照和人物全身：只锁定脸型、五官、年龄感、发型和身体比例。
- 猫咪正面和猫咪侧面：只锁定脸部、灰白毛色分区、虎斑、眼睛、尾巴和体型。
- 线条与材质、室内画风、户外画风：只锁定二维治愈画风、色彩、光线和材质。

不要把服装造型图、场景图、开场锚点、视频帧或尾帧加入全局 Canon。

### 5.2 按需生成的资产

先运行“视觉资产准备”，由 AI 给出建议，人工确认后逐张生成或上传：

| 资产 | 归属 | 是否建议 | 只负责 |
|---|---|---:|---|
| 春日儿童常服 | project | 是 | 浅米色短袖、蓝灰短裤、浅色帆布鞋 |
| 太阳与云朵菱形风筝 | project | 是 | 纸面图案、竹骨结构、包边、彩色尾带、尺寸比例 |
| 窗边木桌空环境 | scene 1 | 是 | 窗户、木桌、椅子、室内光线和空间关系 |
| 春日开阔草地空环境 | scene 2 | 是 | 草地、树木、步道、天空、午后光线和地平线 |
| 胶带、普通彩纸、线轴、草叶 | 无独立资产 | 否 | 由文字描述 |

AI 只提出资产建议，不自动产生图片费用。每张图片生成前单独确认。

### 5.3 资产图片要求

服装图：

- 使用中性站姿，清楚展示衣服和鞋。
- 人物 Canon 只负责身份，服装图不得改变脸、发型、年龄或体型。
- 不表现系尾带、奔跑、放飞等剧情高潮。

环境图：

- 优先为空场景，只保留固定家具和空间结构。
- 室内图不得包含已完成的风筝或正在动作的人物。
- 草地图不得包含已经飞在空中的风筝。

风筝道具图：

- 完整展示菱形结构、细竹骨架、浅米白纸面、天蓝包边、橙色太阳、两朵白云和彩色短尾带。
- 不要用手部或猫爪遮挡结构。
- 同一批准版本贯穿三个片段。

每张候选图执行：生成 V1 → 大图检查 → 批准、拒绝或填写一个主要修正要求生成 V2。重试不得覆盖旧版本。

## 6. 场景视觉基准

场景视觉基准负责共同服饰、环境、道具和画风，不是视频首帧。

### 6.1 场景一

推荐跳过独立场景视觉基准，直接使用：

```text
室内空环境 + 春日儿童常服 + 风筝道具 + 人物/猫咪 Canon + 室内画风
```

这些资产用于生成片段一开场锚点。若实际生成多次出现桌椅位置漂移，再补充场景一视觉基准。

### 6.2 场景二

建议生成一个场景视觉基准，内容为：

- 同一套春日常服；
- 同一只风筝和线轴；
- 同一片开阔草地、树木、步道和午后光线；
- 人物、猫咪和道具保持静态稳定展示。

禁止在场景基准中表现风筝已经高空飞行、人物奔跑或猫咪扑影子的动作结果。批准后可作为片段二开场锚点生成的场景输入。

## 7. 开场锚点与 Provider 互斥模式

### 7.1 静态开场稿

锚点只表现动作开始前的稳定状态，不得注入完整视频动作链。

片段一开场稿：

> 春日上午的窗边木桌，小孩坐在桌前，未系好的彩色尾带放在风筝尾部旁边，双手尚未开始打结；灰白猫蹲在相邻椅子上注视尾带，前爪尚未伸出。风筝、竹骨、尾带、人物和猫咪都完整可见。

片段二开场稿：

> 午后开阔草地，小孩站在迎风方向，一手扶着仍立在草地上的完整风筝，一手握住线轴；灰白猫站在彩色尾带旁边观察。风筝尚未离地，线尚未完全绷紧。

片段三优先使用片段二批准视频尾帧，不另外生成图片。

### 7.2 锚点生成输入

片段一：

```text
风筝道具 + 室内环境 + 春日儿童常服 + 人物/猫咪 Canon + 室内画风
```

片段二：

```text
风筝道具 + 场景二视觉基准/草地环境 + 春日儿童常服 + 人物/猫咪 Canon + 户外画风
```

图片生成输入按资产 ID 和 SHA-256 去重，最多 14 张。批准锚点只归属于对应片段。

### 7.3 视频请求的互斥规则

在片段生成台查看最终 `ShotGenerationSpec`：

| 模式 | Provider 实际输入 | 允许情况 |
|---|---|---|
| `first_frame` | 仅 1 张批准锚点 | 本手册三个片段的默认方式 |
| `reference_media` | 片段/场景/项目普通参考图，最多 9 张 | 没有首帧且需要多图约束 |
| `text_only` | 0 张图片 | 纯文字生成 |

本流程使用 `first_frame` 时，提交前必须同时看到：

```text
providerInputMode = first_frame
actualInputCount  = 1
actualInputs      = 当前片段批准锚点
ready             = true
```

如果页面仍显示要把 Canon、场景基准或道具图作为视频普通参考一起提交，立即停止，不要点击生成。首帧模式和普通参考媒体不能混用。

## 8. 尾帧连续性

片段一和片段二属于不同地点，不采用上一尾帧；合成时使用淡黑完成时间和地点跳转。

片段二批准后提取尾帧，作为片段三的候选开场。采用前检查：

- 人物、猫咪、风筝和线轴均可识别；
- 没有严重运动模糊、肢体变形或错误数量；
- 风筝高度、线轴方向和片段三第一镜一致；
- 人物与猫咪运动方向可以自然延续；
- 来源仍是当前批准的视频版本，没有过期。

满足条件后点击“采用上一片段尾帧”，将其批准为片段三唯一开场锚点。若不满足，保留历史尾帧并改为生成独立开场图，不强制连续。

## 9. 视频生成、审核与版本重试

三个片段逐一处理，不要一次连续提交全部付费任务。

### 9.1 每个片段生成前

1. 确认分镜正文和 12 秒时长已经保存。
2. 确认开场锚点已批准且属于当前片段。
3. 打开 Prompt 预览，先看创作正文，再看专家调试区。
4. 核对 Provider 模式、实际输入数量、素材映射、输入哈希和阻塞原因。
5. 确认输出为 480p、9:16、12 秒，使用自然环境声和动作声。
6. 页面明确提示本次产生 Ark 费用后，再提交一次。

### 9.2 审核标准

- 人物保持同一脸型、年龄感、短波波头和体型。
- 猫咪保持灰白毛色、虎斑、眼睛、尾巴和体型。
- 服装、风筝图案和场景空间与批准资产一致。
- 动作起点、路径、接触对象和结果符合分镜。
- 不出现穿透、悬空、角色分身、无原因换装或道具自动恢复。
- 每个片段只表达一个生活微事件，结尾有稳定状态。
- 环境声和动作声同步，无字幕、水印、Logo 和供应商 UI。

### 9.3 重试和历史版本

- 不合格的 V1 标记为拒绝，填写一个最重要的修正目标，再生成 V2。
- 原视频、Prompt、实际输入快照和输入哈希永久保留。
- 分镜、时长、锚点或素材发生变化后，旧视频显示“基于旧输入”。
- 基于旧输入的视频仍可查看和下载，但不应静默当成当前版本。
- 只有批准并选中的视频用于尾帧提取和成片。

## 10. FFmpeg 成片编排

三个视频均批准后进入成片编排器，按下列顺序添加：

| 顺序 | 片段 | 从上一片段的转场 |
|---:|---|---|
| 1 | 猫咪意外帮忙系好风筝尾带 | 无 |
| 2 | 草地上准备并让风筝离地 | `fade_black`，500 ms |
| 3 | 风筝升空，猫咪追逐影子 | `cut` |

选择规则：

- 室内到户外是时间和地点变化，使用短淡黑。
- 片段二到片段三是同一动作连续，使用硬切并依赖尾帧锚点。
- 不为所有片段统一添加叠化，以免削弱动作连续性。

提交本地合成后检查：

- FFprobe 可读取三个输入视频；
- 片段顺序、音轨、比例和方向正确；
- 淡黑只出现在室内转户外的位置；
- 成片总时长约为 35–36 秒；
- 输出资产可播放、下载并归属于当前项目；
- 批准最终成片 Revision 1。

## 11. 任务恢复与故障处理

### 11.1 页面刷新后重复通知或状态变化

1. 先打开全局任务中心，不要重复点击生成。
2. 以持久化工作流步骤的状态为准，运行时进度只作补充。
3. 页面首次加载只应同步历史，不应反复弹出同一成功通知。
4. 若同一任务状态持续振荡，记录 `jobId`、`stepId`、`operationKey` 和浏览器控制台错误后停止新增付费任务。

### 11.2 长任务或服务重启

- 已提交任务不会要求用户停留在原页面。
- Provider 视频任务已有任务 ID时，重启后使用恢复查询，不重新付费提交。
- `submission_unknown` 表示提交结果不确定，只允许对账。
- 失败任务不会回滚已经保存的剧情、分镜或素材选择。

### 11.3 HTTP 400：首帧与参考媒体混用

典型错误：

```text
first/last frame content cannot be mixed with reference media content
```

处理：

1. 返回片段生成台，打开“生成设置”和“实际参考图”。
2. 若已经采用批准开场图，模式必须为 `first_frame`。
3. 确认实际输入只有一张批准锚点，`actualInputCount=1`。
4. Canon、场景、服装和道具图片只能用于重新生成锚点，不能与首帧一起直接提交视频。
5. 重新生成本地 Prompt 预览，确认输入哈希变化后再提交。

不要通过删除历史媒体或反复重试同一错误请求解决该问题。

### 11.4 HTTP 409：Revision 或输入已过期

409 是并发和历史保护，不是 Provider 生成失败：

1. 重新加载当前场景或片段工作区。
2. 查看最新剧情、分镜、草稿 Revision、素材选择和输入哈希。
3. 重新打开 Prompt 预览。
4. 确认接受的是基于当前 Revision 的版本后再提交。

不要用旧页面强行覆盖新版本。

### 11.5 锚点身份不稳定

- 重新生成开场锚点，并在锚点生成阶段检查人物、猫咪、服装、环境和风筝职责。
- 不要为了修复身份而在 `first_frame` 视频请求中追加 Canon 普通参考图。
- 每次重试只写一个主要修正目标，例如“恢复批准人物的短波波头和脸型”。

### 11.6 资产缺失或破图

- 检查资产是否显示 `contentReady=true`。
- Canon 文件缺失时，先在停止付费操作后执行 Canon 修复流程。
- 项目、场景或片段资产缺失时重新上传或重新选择所属项目的版本，不把生成媒体移动到 Canon。
- 图片数量超过图片 14 张或视频 9 张上限时，在提交前精简职责重复的资产。

### 11.7 FFmpeg 或 FFprobe 不可用

重新执行：

```powershell
Set-Location "D:\soft\AI\company-project\cat-video-generator"
uv run cvg doctor
```

解析顺序应为有效显式配置、系统 `PATH`、不可用。不要把另一台机器的用户目录绝对路径写入 `.env`。

## 12. 费用操作预估

在不执行剧情诊断和重写、每张图片和每个视频均一次通过的理想情况下：

| 类型 | 预计次数 | 说明 |
|---|---:|---|
| 分镜导演 LLM | 2 | 两个场景各一次 |
| 视觉资产规划 LLM | 最多 2 | 两个场景各一次，可按需跳过 |
| 片段视觉/Prompt 审稿 LLM | 2 | 片段一、二生成锚点前确认静态开场稿；片段三可复用尾帧 |
| Seedream 图片 | 7 | 服装、风筝、两个环境、场景二基准、两个独立锚点 |
| Seedance 视频 | 3 | 三个片段各一次 |
| FFmpeg 本地合成 | 1 | 不产生 Ark 调用 |

拒绝候选并生成新版本会增加相应调用。每次付费操作都应在页面看到模型、输入、素材数量和费用提示后单独确认。

## 14. 默认决定

- 使用完整剧情入口，不重复执行主题扩写。
- 剧情诊断可选，剧情重写默认跳过。
- 两个场景、三个独立 12 秒片段，目标总时长约 35–36 秒。
- 人物和猫咪身份始终继承全局 Canon，不建立项目级重复身份包。
- 服装、环境、关键风筝和场景视觉基准按需生成。
- 场景视觉基准不是视频首帧。
- 片段一、二生成独立开场锚点；片段三优先采用片段二尾帧。
- 视频默认使用互斥的 `first_frame` 模式，只提交一张批准锚点。
- 每次生成独立确认费用，失败和重试不覆盖历史。
- 只批准的视频参与尾帧提取和成片。
- 最终使用 FFmpeg 本地合成，不做一次调用生成完整长视频。
- 不引入角色 LoRA、多智能体、节点画布、视频参考或音频参考。
