# 双播放器、场景参考与镜头生产

本轮接续 `VIDEO_CANDIDATE_TRIALS.md`。以下为新的运行行为；此前单文件并排比较及旧测试记录属于历史实现。

## 真实比较与范围

- 比较左侧为候选冻结父 EDL 的 `edit_trial_base`，右侧为所选试装的 `edit_preview`。当前草稿版本另行显示，历史候选不会被改绑到最新草稿。
- 新本地试装只物化两份完整视频和真实缩略图，不再生成 `hstack` 查看文件。Job 的 `providerResult.comparison` 返回 `beforeAssetId`、`afterAssetId`、父版本、父哈希、试装哈希。历史 `edit_comparison` 仍有查看入口。
- 两个视频由同一组件管理定位、逐帧、播放、循环与发声侧。使用 `requestVideoFrameCallback` 观察呈现帧；超出一帧偏差时停止并重新定位，缓冲或错误不会继续推进另一侧。不承诺所有设备永久零误差。
- 原始候选位置与取用决定独立。候选轨的固定长度窗口支持拖动、方向键和数字输入；画面与候选声音共同移动。范围变更会使旧试装过期，应用仍引用已完成 Job 并核对父版本和准确 EDL。
- 查看接头包括替换区间及前后各 24 帧，限制在完整视频内。单帧选区保持在所选帧。

## 场景与分镜

- 新环境图输入只有画风板与空场景描述，保留空间、家具、光照及稳定道具事实；不再额外发送儿童、猫咪图片来匹配画风。
- 新分镜任务使用 `catflow-director-v8-performance`、`referenceInputMode=vision`，实际发送冻结的五张图片，同时明确编译环境意图、故事原文和因果链。空间冲突使用原有风险字段，在同一次规划输出中返回。
- 旧分镜任务仍执行原文本路径。界面区分来源规划方式，手工保存不被当作新的模型读图。
- 每个 ShotSpec 可保存 `sceneAssetId`、`environmentUse`（`recompose` / `preserve_layout`）和 `confirmedFrame`。这些值保存在现有不可变分镜版本的 JSON 中，无须新数据库表。

## 按需镜头画面

分镜卡提供已有图片选择、从真实视频保存帧、本次图片输入预览和明确的付费生成按钮。空环境图与含角色的镜头画面职责分开。

确认画面需要身份比例、位置状态、运动空间、动作起点、相邻连续性五项人工判断。服务端校验图片所属项目及哈希。确认引用记录图片 SHA256、设计哈希和判断项；设计哈希包含相关镜头内容、场景意图、实际参考 ID 和 SHA256，不包含版本 ID 或确认记录本身。派生动作摘要与保存操作采用相同规范化，避免首次确认模型分镜时立即过期。旧画面不会因设计变化被删除。

`shot-production` 接口提供 `context`、`preview`、`generations`、`confirm-frame`、`extract-frame`、`assemble`。图片、视频和本地取帧复用 Asset / Job，冻结 `purpose`、`targetShotId`、分镜版本和设计哈希。付费任务在项目锁内检查同镜头同用途的未终结任务；结果未知时不创建另一份任务。

## 两种视频路径

- 默认整片一次生成。已确认镜头画面和单独绑定的场景按实际用途作为普通参考，超过当前模型图片上限时阻止提交，不丢弃参考。Prompt 编译版本为 `seedance-professional-v6-scene`。
- 用户主动选择逐镜头模式。每个镜头只发送一张已确认的严格 `first_frame`，不混入其他图片或视频参考，仍使用当前 Ark 模型。每个镜头独立提交与核价，不自动批量提交或重试。
- 模型生成长度至少 4 秒；用户等长取用至镜头目标。只允许实际 24 fps 且帧数充足的素材。
- 组装服务验证当前分镜、每个镜头的设计哈希和取用范围，构造 EDL v3，进入新草稿。视频和声音引用各镜头真实素材。分段音轨保留来源 Job 证明，即使后续整段画面被替换，保留声音模式仍可继承原镜头音轨。
- 声音不存在或请求后缺失按实际媒体显示；组装不会补造模型声音、声源分离或自动混音。正式采用仍需完整验收。
