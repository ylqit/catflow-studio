# 外部任务状态、回执保存与异常恢复

实施日期：2026-09-08。已在本机 8877 服务启用，迁移版本 `0031_job_execution_recovery`。本轮没有发起新的真实模型生成。

## 1. 判断边界

前端始终使用本地 `jobId`。供应商 Task ID、Response ID、客户端关联编号和服务端请求编号分别保存；请求追踪编号不能用于冒充任务查询编号。

`Job.status` 表示整体进度；`execution` 同时表达外部状态、最后确认时间、本地阶段、恢复状态、原始错误、用量是否取得及可执行动作。HTTP 查询失败只更新查询错误，不把外部任务改成失败。外部成功、本地下载或保存失败仍保留外部成功事实。取消本地等待不能推断远端已取消。

已完成的本地结果与内容质量通过互不等价。结构校验失败保留正文，不能自动采用。缺少用量显示待核实，不能算成零费用。

## 3. 冻结契约与回执

新任务保存契约版本 2、供应商接口类型、实际 endpoint/model、超时和保存策略。相对保存期限纳入冻结配置；提交时计算绝对时间，供应商实际返回的 `store` / 到期时间另行登记。

保留原业务 `inputHash` 算法，在冻结输入内增加由业务哈希和执行契约共同计算的 `executionInputHash`。未知任务再次生成的确认绑定此执行哈希。历史任务和历史业务哈希不回写；不是将所有历史 Preview 哈希重新计算。

回执目录在运行工作目录下的 `provider-receipts/<jobId>/`。先写临时文件、flush/fsync，再原子更名；登记内容哈希、接收时间和引用。数据库暂时不可用时保留磁盘回执，恢复登记不会重新 POST 生成。工作目录必须纳入持久备份，不能当成可随时清理的普通缓存。

流式检查点按 0.5 秒检查或 16 KiB 阈值保存，创建和终态事件立即登记。当前接收正文有 2 MiB 上限；超过时保留已收到证据并进入异常处理，不无限占用内存。原始返回与解析结果分别保存。详情返回经过筛选的内容，不暴露凭据或临时下载地址。

本地进度当前主要归并为准备、提交、查询、解析问题、保存、完成；下载与媒体校验发生在保存过程内，不假装具有每个媒体子步骤的独立实时百分比。

## 4. 三类外部接口

| 类型 | 新任务行为 | 恢复条件 |
|---|---|---|
| 视频异步任务 | 创建回执立即保存 Task ID；查询正文先登记，再解释排队、运行、成功、失败、取消、过期 | 有可信 Task ID 则查询原任务；成功结果优先继续本地保存 |
| Responses 文本、规划与诊断 | `store=true`、`stream=true`、`caching={type: disabled}`；收到 `response.created` 保存 Response ID | 有可检索编号、保存证据及有效期限时查询；无编号保持提交未知 |
| 当前同步生图 | 保持模型和接口；先保存返回地址、请求编号、用量与正文，再下载 | 有结果则恢复下载；没有 Task 能力就不提供查询生图任务 |

`ARK_RESPONSE_RETENTION_SECONDS` 默认 259200（3 天），当前实现允许 1–259200 秒。仅改变新任务；本地已收到的结果继续保存。没有添加 SDK 不支持的后台生成参数，不承诺流中断后远端一定继续执行。

所有创建调用保持 SDK 隐式重试关闭。冻结的 endpoint 与当前运行环境不一致时不能静默改用另一环境提交或查询。

## 5. 调度、并发与重复执行

恢复优先级：完整本地结果 → 已收回执 → 可查询编号 → 确定未提交的首次创建 → 无编号的未知提交。查询和本地恢复使用原 Job；新的模型创建使用新 Job。

| 参数 | 默认值 |
|---|---|
| 正常查询 | 5 秒 |
| 查询异常退避 | 5、10、20、40、60 秒，随后维持 60 秒并加小幅随机偏移 |
| `Retry-After` | 使用更长的服务端等待时间 |
| 查询窗口 | 30 分钟或连续 12 次查询异常后等待人工核实 |
| 本地暂时异常 | 最多 3 次自动恢复；结构问题不循环重试 |
| 租约 | 60 秒，独立数据库会话每 15 秒续租 |
| 执行通道 | 提交、查询、本地处理各 1 个槽位 |
| 超时 | 连接 10 秒；查询读取 30 秒；文本空闲 120 秒、总接收 30 分钟；同步生图读取 600 秒 |

下一次调度时间与租约过期时间独立。接管递增租约代次；业务保存校验执行者、代次和有效租约，覆盖 ORM flush 与批量写入。失去租约的执行者可以登记已收到的回执，不能继续物化业务状态。

已知终态不被旧的运行中事件覆盖。冲突回执保留；明确的同终态查询可解除旧状态冲突，编号冲突不能据此自动消除。损坏的回执暂停所属任务，不阻塞其他任务，也不导致重新创建。

## 6. API 与界面

| 接口 | 含义 |
|---|---|
| `GET /api/v1/jobs/{id}` | 只读本地摘要与 `availableActions` |
| `GET /api/v1/jobs/{id}/events` | 分页执行历史与游标 |
| `GET /api/v1/jobs/{id}/result` | 本地正文、错误或素材引用，标明完整、部分、缺失 |
| `POST /api/v1/jobs/{id}/recovery` | 按预期修订号和幂等键安排 `query_provider` 或 `process_result`，返回 202 |
| `POST /api/v1/jobs/{id}/resume-storage` | 兼容入口，复用统一恢复规则 |
| `POST /api/v1/jobs/{id}/replacement-preview` | 生成准备，不创建模型任务 |
| `POST /api/v1/jobs/{id}/replacement` | 一次明确确认后创建关联的新生成；可能收费 |

按钮由服务器可执行动作决定，服务端再次校验。恢复重复点击合并；修订冲突返回当前事实。普通刷新和 SSE 重连不会触发远端查询或生成。

每个窗口共享一个事件连接，携带项目、系列、来源文档归属，支持 `Last-Event-ID` 和 Job 修订号。接入后获取本地快照；前台活动任务每 5 秒兜底，后台暂停兜底，重新可见时核对。故事、分镜和素材页面在任务更新后刷新相应业务列表，不能只刷新父工作区。

任务详情展开前后均区分“尚在读取详情”和“确实没有正文”。重新准备弹窗为原生 modal，展示当前模型、时长、参考和指令，确认默认不勾选。未经一次明确确认，不能提交新的付费请求。

## 7. 未知任务的新生成与晚到结果

“保留此记录，重新准备一次生成”保留旧未知记录。确认绑定旧 Job、新执行输入哈希和此次幂等键；生产对象锁、确认校验和新 Job 创建在同一事务内完成。相同幂等键返回原新 Job；另一窗口不能复用确认再次创建。

新 Job 通过 `supersedesJobId` 关联旧任务，旧详情保留后续入口。旧结果晚到时保存为历史结果；结构化结果不覆盖当前故事、来源分析或分镜。晚到媒体仍可保存不可变素材，不能自动选择、采用或替换封面。

## 8. 迁移与运行维护

`0031_job_execution_recovery` 追加 Response ID、客户端编号、execution JSON、修订号、租约代次、下一次调度时间及相关索引，兼容旧字段为空。旧成功任务且本地结果完整时不在启动阶段批量查询；可信编号的未终结任务可以恢复，旧失败任务通过页面显式核实。

启用过程先确认没有活动请求，再停止服务、迁移和启动。2026-09-08 实际启用前活动任务为 0，服务及 Worker 启动成功。迁移后的旧业务表行指纹保持不变。

回退代码时保留新增列与回执；本迁移的 `downgrade()` 明确拒绝删除恢复历史。需要处理部署问题时应前向修复，不删除回执、不手工将未知任务改成失败、更不能以数据库补状态代替页面确认。

若有外部编号，使用页面“查询原任务”；若已取得结果，使用本地恢复；若没有编号或正文，查看错误并决定是否重新准备。没有收到任何回执前中断的受理窗口仍无法彻底消除。
