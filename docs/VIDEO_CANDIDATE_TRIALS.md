# 视频候选、免费试装与音画草稿

本次实现基于 `7ee0030`，接续 `VIDEO_EDIT_DRAFTS.md`。后续双播放器和场景参考改造见 [DUAL_PLAYER_SCENE_PRODUCTION.md](DUAL_PLAYER_SCENE_PRODUCTION.md)。生成、试装、应用和正式采用分别保存事实，不再把生成前的候选核心范围当作唯一可用裁取。

## 使用流程

1. 在编辑工作区准备当前完整草稿预览，定位问题区间。
2. 明确选择生成路径和本次声音请求，再检查实际参考清单与完整指令。只有“生成修改结果（付费）”创建模型任务。
3. 返回的候选按父版本分组。查看“模型原始结果”可以独立定位完整素材，查看位置不修改取用范围。
4. 设置候选取用起点。取用长度等于替换长度，完整草稿总帧数不变。可保留父草稿完整声音，或使用候选原生混合音轨；候选声音与画面使用相同取用位置。
5. “准备试装对比（本地免费）”冻结新的本地 Job，输出修改前与真实完整试装两份独立视频，使用双播放器联动。静音为默认；试听时选择唯一发声侧并保留定位帧。窄屏可放大任一侧。
6. 修改取用或声音设置后，旧预览显示“对应上一份试装”，应用按钮禁用。历史试装仍能选择和查看。
7. “应用此试装到草稿”引用已经完成的本地 Job，创建新草稿版本。父版本发生变化时阻止应用，不自动合并。
8. 准备新草稿完整预览，完成准确音画版本的验收后，才可正式选择。新声音版本增加声音意图、同步与连续性判断；有意无音轨时，同步与连续性标记不适用。

候选可以保留并继续准备下一次修改。未终结及提交状态未知的模型任务仍阻止重复提交。候选是否曾经应用，和当前草稿是否仍使用它，分别展示。

## 冻结契约

生成前的 `candidateCoreRange` 保持在原付费任务中作为建议，不回写。新的免费试装请求示例（帧范围均为左闭右开）：

```json
{
  "expectedEditVersionId": "父草稿版本 UUID",
  "expectedTimelineHash": "父时间线哈希",
  "repairId": "候选所属修改 UUID",
  "placement": {
    "candidateSourceRange": { "startFrame": 36, "endFrame": 84 },
    "audioPolicy": "use_candidate",
    "fadeInMs": 0,
    "fadeOutMs": 0
  },
  "idempotencyKey": "本次本地试装幂等键"
}
```

`render_edit_preview` 的冻结输入保存父版本、父时间线哈希、父 EDL、候选、取用与声音方案，以及服务端构造的新 EDL 和哈希。历史父版本允许创建试装；只有应用需要当前草稿头的比较并交换校验。

应用请求增加 `previewJobId`，同时携带预期父版本、哈希和 `repairId`。服务端验证 Job 属于此项目与草稿、由本地处理器完成、具有对应完整预览，重新构造冻结方案并核对 EDL／哈希。浏览器不负责再提交一份新 EDL。旧版直接提交 v2 的保存接口保留兼容；新的 v3 试装必须绑定完成记录。

试装资源沿用现有 Job 和 Asset：

| 角色 | 用途 |
| --- | --- |
| `edit_preview` | 实际完整试装或当前完整草稿 |
| `edit_trial_base` | 从冻结父 EDL 物化的比较左侧 |
| `edit_comparison` | 历史并排查看资源；新试装不再强制生成 |
| `edit_thumbnail` | 对应实际显示文件的帧证据 |

比较两侧均调用现有 `render_timeline` 物化准确 EDL；新比较在浏览器中联动两个独立视频，历史并排文件只保留查看兼容。

## EDL v3 与声音

`0028_video_trials_audio` 仅扩展版本约束以允许 v3，不改写旧 EDL。v1／v2 的格式和解释保留；兼容转换发生于新试装或新草稿版本。

v3 使用顺序音频区段，保存来源 Asset、SHA256、源入点、时长和可选候选来源。总音频区段长度必须等于视频长度。候选淡入淡出以原始源区间为锚点；第二次修改切开一个区段时保留其原淡化包络，不在切开位置重新套淡化。

默认直接拼接。淡入／淡出以整数毫秒配置，默认 0，总长不能超过候选取用区段。不自动交叉混音、不分离声源、不添加配乐。无音轨的父素材在对应时段保持无声；存在但自然短于视频的音轨，其剩余时段按静音处理，不复制或延长视频动作。

新分段音轨统一重采样为 48 kHz。单声道项目保持单声道；父轨为立体声时输出立体声，超过两声道的来源会下混为立体声，不将复制声道描述为音质提升。历史 v2 的原轨保留策略继续执行。

## 原生声音与两种生成路径

- 新完整视频请求明确发送 `generate_audio=true`，沿用分镜已有环境声、物件声、动作声、音乐和对白设计。只有没有声音设计的旧分镜在新编译时得到自然环境／动作／物件声的缺省描述。编译版本为 `seedance-professional-v5-audio`，历史已冻结 Prompt 不重编译。
- 局部请求冻结 `generationMode`、`audioMode`、`soundDescription`、起始／结束参考帧和 `generateAudio`。声音是否用于草稿由免费试装另行决定。
- `edit_existing` 发送冻结上下文视频、普通入出点参考及五张来源参考。入出点通过提示词说明用途，不标为严格首尾帧。上下文继续无声，避免把错误动作声音重新送给模型。
- `from_frame` 必须明确选定正确起点，只发送 `first_frame` 和可选 `last_frame`；不发布上下文视频，不混入五张来源参考。原结尾需要替换时，不发送原尾帧。
- 当前模型保持不变，不发送仅较新模型支持的显式 `omni_reference_task_type=edit`，不自动升级或重试。

新落盘素材通过 ffprobe 读取实际解码帧数、帧率、声道和采样率，通过音频检测区分静音音轨与无音轨。请求声音却没有返回音轨时保留付费素材并标明问题，不自动重试；可免费改为保留父草稿声音。历史记录不回写，缺少检测信息时明确显示未知。候选实际帧率不符合当前 24 fps 试装时间基准时明确拒绝，不静默变速或复制帧。
