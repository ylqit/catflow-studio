# Prompt 编译与生成输入治理

本轮沿用现有故事、系列、导演模型与调用次数。仅修改已有调用的专业指令、输出契约和媒体文本编译；没有新增独立 AI 审查、自动重试筛选或自动重生成历史视频。

## 当前行为

- 系列、分段与单集策划明确本集参与者、道具数量、起点、目的和结束状态，区分身份连续性与本集重置的场景和道具。环境设计区分固定陈设、移动道具和携带物，不把动作结果提前放进环境图。
- 导演在同一次调用中观察实际参考图，检查物体数量、接触面、落脚点、活动空间以及与故事的冲突。空间、构图、走位、因果变化、声音和结尾须互相一致，无法确定的事实留在现有待处理意见。
- 新导演输出契约 `professional-director-v4-performance` 要求每个镜头提供 `cameraSpatialRelation`、`interactionConstraints`、`visualExclusions` 和 `actionBeats`。后两项无适用内容时可明确提供空列表。模型结果接收和手工修订恢复使用同一契约；缺项返回具体字段路径，不自动猜测。
- 分镜卡与未完成导演草稿均可用中文控件编辑这三个字段。旧分镜允许缺省。非空设计变化参与镜头设计哈希，使原起始帧确认过期；历史空字段不改变旧哈希。
- 新分镜以节拍为时间和动作顺序的来源，走位保留空间起止；旧分镜仍以走位和物理变化为动作来源。整集使用累计时间区间；单镜头只取当前镜头；起始图只取初始状态和静态构图，不发送完整交互动作链、结束状态或声音；片段修复保留修改范围、保留内容及结束目标。
- 连续性按已确认的继承、调整或重置决定编成自然语言，并放在逐镜执行之前。省略内部键、空值和空数组，使用道具名称、自然语言归属及本集开场标签。
- 审查风险与流程意见独立展示。明确的交互关系属于正向设计，`visualExclusions` 属于负面约束；不再把 `generationRisks` 整体拼进负面文本。
- 最终参考图职责由实际提交顺序编译。角色比例图明确属于同一组角色；普通镜头参考、严格首尾帧及视频参考各自有明确职责。无法映射的角色标识和系统生成字段中的未解析模板占位符会报告来源，阻止提交；不静默删除文本。用户自定义媒体正文保持原样。

## 版本与追溯

| 内容 | 当前版本 |
| --- | --- |
| 导演提示词 | `catflow-director-v7-performance` |
| 导演输出契约 | `professional-director-v4-performance` |
| 整集视频编译 | `seedance-professional-v9-performance` |
| 镜头媒体编译 | `catflow-shot-production-v3-performance` |
| 局部编辑编译 | `segment-edit-v8-performance`（现代契约）、`segment-edit-v6-performance`（旧创建契约） |
| 新媒体任务发送标记 | `providerPromptVersion: 1` |
| 新整集／修复／环境输入快照 | `schemaVersion: 3` |

预览的 `compiledProviderPrompt` 是最终完整文本，包括正向、负向与参考职责。创建任务时冻结该字段并将其纳入输入哈希；Worker 对带新标记的任务要求此字段存在，SDK 直接发送它，不再追加隐藏的英文角色说明。单镜头及其他图片任务同样在既有 `frozenInput` 中保存最终文本。

旧任务按其冻结版本继续解释；旧快照缺少最终文本时，界面标明它只能展示已记录正文，不从当前项目状态重建“历史完整指令”。旧导演 v2 结果仍可恢复。没有数据库迁移、批量回填或历史媒体替换。

## 验证与后续效果观察

离线回归入口：

- `tests/catflow/test_prompt_governance.py`：六集冻结数据、继承／调整／重置、通用空间场景、初始图时间语义、占位符来源和 SDK 文本。
- `tests/catflow/test_provider_prompt_boundary.py`：预览 → 创建任务 → Worker → 模拟 SDK 的逐字一致，覆盖整集、环境、镜头图／视频、片段修复、严格首尾帧、替换结尾，以及新旧导演手工恢复契约。
- `tests/catflow/test_director_result_normalization.py`、`test_video_generation_prompt.py`、`test_workflow.py`：输出契约、旧结果、标点保留、幂等与生成流程。
- 前端组件回归验证字段保存、缺项与空列表区别、候选差异、原样复制、历史记录提示与请求读取失败。

六集冻结样本仅用于回归编译，没有新增项目名称或道具关键词分支，也不将旧分镜的空间事实自动补成新设计。

下一次用户正常提交模型生成时，分别记录下列项目。离线验证能证明输入编译与追溯正确，不能证明视频模型必然遵守每条约束。

| 观察项 | 检查内容 |
| --- | --- |
| 主体归属 | 肢体与工具是否连接正确角色，接触效果是否发生在接触处 |
| 空间一致 | 摄影机、主体、表面、背景、内外侧及遮挡是否一致 |
| 物体数量 | 同一物体移动后是否仍为同一实例，背景是否额外复制道具 |
| 动作因果 | 起点、运动、接触和结果是否形成完整可见过程 |
| 参考吻合 | 身份、比例、环境及道具起始状态是否遵守各图职责 |
| 时间可执行 | 主动作和必要反应是否能在目标时间完成，声音是否同步 |

每项区分“输入已经明确但模型未遵守”与“输入仍有歧义或冲突”。若问题在参考图初始状态或正式设计，应先修正相应输入，再由用户明确提交新任务；不以自动付费重试筛选效果。

- 后端直接相关的 94 项测试通过。最终追加复核系列、工作流、API → Worker → SDK、六集编译及修复时间坐标，共 70 项通过；两组存在重叠，不能相加。
- 前端完整 29 个测试文件、170 项测试通过。最终 `npm run build` 完成 OpenAPI 导出、类型生成、`vue-tsc --noEmit` 与 Vite 生产构建。
- 全仓库回归发现 16 项原有失败，已在改动前的 `0c1f4bc` 代码副本及独立测试库逐项复现。主要是旧片段编辑测试仍允许小于 4 秒的修改，或未准备实际参考便尝试创建任务；本轮没有改动这些生产限制。
- 排除上述 16 项后，广域检查为 358 通过、1 项断言失败：旧断言把入集连续性固定查找在结尾段。新版有意将其放到逐镜执行之前，断言已同步更新，随后整组系列与相关工作流复测通过。
- 独立审查发现并修复了任务装配、首图时间语义、未解析占位符、手工恢复契约及候选历史展示的遗漏。
- 一轮早期混合测试误用了本地业务库，留下两个无生成任务的测试项目。已按精确 ID、创建时间、名称和无任务条件备份并清理；直接核对六集的采用故事、分镜及内容、最新视频任务和冻结参考清单，均与开始时一致。后续数据库回归均使用自动销毁的独立测试库。

未提交真实模型生成，也未重启当前本地服务。构建产物已更新；使用新后端编译和导演契约前应重启 API 与 Worker，然后刷新页面。已有视频与历史输入不自动更新。
