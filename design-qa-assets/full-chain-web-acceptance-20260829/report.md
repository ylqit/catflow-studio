## 4. Web 业务链路

1. 从旧版看板新建独立试验项目，填写 8 秒、9:16、quick 和固定主题。
2. 在 Web 编辑创作要求，生成故事候选，选择并保存当前剧情版本。
3. 通过 Web 应用全局不可变 Canon 基础证据，并生成、审核本集儿童、本集猫咪和同框比例设计。
4. 在 Web 导演分镜工作台生成并整理为一个 8 秒连续镜头，保存 Storyboard Revision。
5. 生成视觉资产规划；保留一个窗边环境参考，Scene Look 与首帧锚点保持关闭。
6. 生成并审核环境参考；编译生产 Prompt，批准制作包。
7. 在 Web 费用确认层核对 9 张有序参考、模型、8 秒、9:16、输入哈希后提交一次视频生成。
8. 在 Web 任务中心跟踪 Provider 状态；故障修复后通过页面继续跟踪原 Provider 任务。
9. 在 Web 播放视频、审核并“批准并选择”。
10. 在 Web 建立单片段时间线，配置开场/结尾 `fade_black`，执行本地合成。
11. 播放总片并“批准并设为总片”。
12. 冷刷新，确认四区、视频、时间线和总片完整恢复。

## 6. 执行途中问题与修复

### 6.1 视觉规划前的数据库连接超时

- 页面错误：`(psycopg.errors.ConnectionTimeout) connection timeout expired`
- 调用边界：发生在 Provider 调用前，没有产生重复费用。
- 根因：开发环境数据库连接建立阶段瞬时超时。
- 修复：仅在数据库连接建立边界对 `ConnectionTimeout` 做有限退避重试；不重试已经开始的事务或业务命令。
- Web 恢复：服务重启后从原页面按钮重新提交，成功继续。

### 6.2 节点锚定编辑窗被底部四区定位器遮挡

- 实际影响：编辑器底部主操作不可见/难以点击。
- 修复：编辑窗内部增加底部安全区和滚动空间，使主操作可滚动到固定定位器上方。
- Web 验证：HMR 后按钮可见，操作由页面正常提交。

### 6.3 Provider 成功后的 lease heartbeat 竞态

- 实际表现：Provider 已成功并生成视频资产，但本地 heartbeat 在步骤已经进入终态后仍续租，抛出 `workflow lease heartbeat failed`，把子任务和父级包装任务错误标记为失败。
- 连带表现：第一次 Web “批准并选择”返回 422，因为资产工作流被错误写成 failed，而不是 awaiting review。
- 修复：终态任务 heartbeat 改为干净停止；对具有 Provider task ID、已提交时间和该精确故障证据的视频任务提供 `resume_provider_tracking` 恢复策略。
- 取消/费用语义：恢复动作只重新查询原 Provider task ID，不创建新 Provider 任务；submitted/running/unknown 状态不会通过本地隐藏冒充取消。
- Web 恢复：在全局任务中心点击“继续跟踪原 Provider 任务”，确认同一任务号；任务恢复为待人工审核后，Web 审核返回 200。
- 审计：最初失败的父级包装记录保留为历史审计，没有通过后台清理或伪造成功。

### 6.4 修复和服务重启期间的页面请求超时

- 浏览器历史日志曾记录 `ApiTimeoutError: 请求在 15 秒内没有响应，请检查服务状态后重试`，分别出现在素材工作台刷新生成输入和创作工作流加载期间。
- 发生背景：API 修复和服务重启窗口；页面没有用空白内容伪装成功。
- 恢复：服务就绪后由 Web 页面重新加载；没有直接调用 API 补写状态。
- 最终检查：最后一次冷刷新以后，浏览器日志只有 Vite `connecting/connected` 调试信息，没有新增 error 或 warning。
